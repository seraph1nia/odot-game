# Proposal

## Why

The landed authored countryside has expensive native rendering and previously optimized numerical/presentation paths. A new controlled performance loop must identify remaining actual scaling costs rather than repeating rejected fragment batching or guessing from draw counts.

## What Changes

- Extend the existing owned presentation replay with representative settlement/combat populations, overview/close views and attributable frame/resource measurements.
- Measure unchanged fixed-window numerical scales and implement at most three independent, faithful improvements justified by those results.
- Record matched inputs, actual wall/allocation distributions, rejected candidates and complete verification limits in a performance report.

## Capabilities

### New Capabilities

None: profiling is diagnostic tooling, not a new player capability.

### Modified Capabilities

None: this is an implementation optimization. Existing numerical, presentation, selection, ownership, protocol and authored distribution contracts remain unchanged; `skip_specs: true` avoids inventing behavior changes.

## Impact

Existing Game.Core combat stage queries and Game presentation seams are candidate locations; the reusable DevRunner replay owns diagnostics. No dependency, asset, UI/audio, source-export or numerical-reference changes. The unchanged landed full-CI baseline failed at reconnect casualty admission; retain that result rather than treating it as an optimization regression.
