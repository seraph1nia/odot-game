# Design

## Context

See `proposal.md` for motivation and scope. `Match.Step` orders cleanup/arrivals, simultaneous impacts, elimination, cleared-city observation, transfers, admission, engagement deadlines and new actions. Stable identities, seeded tie ordering and these mutation boundaries are gameplay contracts.

`CombatSimulation.All` collects and sorts the ECS world. `Living`, `Snapshot`, `Soldiers` and `Enemies` create further arrays and DTOs; enemy/soldier filtering follows projection. A continuing four-player tick can perform approximately 13 world collections/sorts and seven complete living-unit projections. A four-player snapshot performs nine living-unit projection passes because each city requests soldiers twice. These are source-derived counts, not measured CPU attribution. Profiles, quotes and definitions are also rebuilt for unchanged inputs.

Waiting actors reconstruct city observations independently. Targeting, splash, exposure and defense queries revisit global actors. Single-target impacts build unused splash candidates. Temporary reachability converts short-lived dictionaries into frozen maps. Presentation rebuilds playback indexes every frame, searches event history per view, samples deployed units twice and evaluates hidden-city rigs. Route points are cached but segment lengths are recomputed.

The existing 21 ordinary strategies cover 172,396 combat ticks in recorded evidence. The successful `speed-up-verification` gate records 252.82s overall and 55.37s for cooperative tests under contention; it is historical verification evidence, not a runtime benchmark. Its 563-input manifest is available for checking baseline eligibility. Preserve that completed, unsynced change's coverage contracts. Default verification uses Debug, two bounded rule processes and serial Arch lifetimes within each process. Default gameplay has four cities at most, 21 cells per city, six capacity per cell and size-two ordinary units; authored boards already support up to 256 cells.

## Goals / Non-Goals

**Goals:** Reduce unnecessary work while preserving exact numerical and visible behavior; measure authority, snapshot/transport and presentation costs independently from test-harness costs; exercise a substantially larger actual fight; retain reproducible before/after metrics and operation counts with explicit scope.

**Non-Goals:** Balance changes, approximate authoritative arithmetic/AI, new seed/tie rules, changed simulation speed or process budgets, protocol/schema/compression changes, renderer replacement, ECS replacement, parallel simulation, general benchmark infrastructure, new NuGet dependencies, or tool installation. Native GPU/compositor performance is not established by software-rendered verification. Event-driven admission/death scheduling, reverse occupancy indexes, persistent cross-stage route caches, component-layout rewrites and pooling are deferred; they require more mutation/lifetime complexity than the selected low-risk fixes.

## Decisions

### 1. Establish separate baseline families before optimization

First add measurement plumbing, counter hooks, fixtures and regression references without changing existing runtime algorithms or campaign-harness behavior. Freeze this instrumented unoptimized source identity as the comparison baseline. Capture all required baseline families successfully before groups that optimize either runtime or testing. If a fixture needs correction, change it before freezing the baseline; later measurement/fixture changes require both sides to be recollected from recorded source revisions. Use isolated checkouts/output directories for such comparisons and never mutate shared build/import output concurrently.

| Family | Fixed workload and measurement | Attribution |
| --- | --- | --- |
| Ordinary runtime | Existing frontline campaign, solo and four players, seed 1, isolated process; other existing selections remain supported | Report complete campaign and combat stepping separately from preparation, assertions and diagnostics |
| Scalability runtime | One-city mixed fight at 128, 512 and 2,048 total actors on the same supported 256-cell board, same seed and 600 ticks | Report setup, stepping, workload distribution and operation counts separately |
| Snapshot and transport | Frozen snapshot fixtures from ordinary and large workloads; identical sample counts and input digests | Report snapshot construction, JSON encode/decode, Brotli encode/decode, payload bytes and allocations separately; isolate codec cost with already captured DTOs |
| Client presentation | Identical ordinary-combat snapshot/event playback and frame-time/focus script in one owned graphical client | Report managed frame-update p50/p95/p99, process CPU, allocations, pose samples and actual renderer/frame settings; setup and screenshot costs excluded from timed frames |
| Verification speed | Before/after `mise run test` and full `mise run ci`, unchanged budgets/pacing/build configuration, all coverage retained | Report task wall time, preparation and rule partitions, scenario execution/admission waits, exports and evidence size separately |

Use `mise run profile-campaign --strategy frontline --players 4 --seed 1 --iterations 3 --configuration Release` and the equivalent solo selection for runtime comparison. Provide explicit Debug/Release selection with Release as the profiling default; leave ordinary CI's Debug configuration unchanged. Every profile uses one separately reported warm-up and 1..10 measured iterations (default three), serially, with bounded execution and disposal. Prepare the selected locked project once outside measured work. The no-argument gameplay-test entry point and xUnit fallback remain intact. Timing uses monotonic elapsed time, process CPU, total managed allocated bytes and GC collection deltas; GC counts are not pause durations. Coarse phase timing must report its overhead and process-wide scope. Record source/configuration hashes, SDK/runtime, machine/OS/CPU, build, warm-up, iteration, concurrency, fixture version and measurement mode. Do not silently auto-install external profilers.

Provide `mise run profile-snapshots --scenario ordinary-and-large --iterations 3 --configuration Release` for the existing snapshot/codec path; link the existing engine-independent codec into a suitable C# measurement executable rather than loading Godot. The command reports each input's fingerprint/digest and separates projection from codec work. No codec optimization is pre-authorized merely by adding its measurements.

Use `mise run profile-presentation --scenario combat-playback --frames 600 --iterations 3 --configuration Debug` under the existing owned private-display harness. Source presentation uses the existing locked Debug Godot configuration; unlike engine-free profiles, it must not invent a generic Release lock file or alter export profiles. Report this build distinction explicitly and compare each family only with its identical configuration. Generate the bounded ordinary-command input stream through checked-in C# fixture setup; preserve its baseline digest and feed the same snapshots, events, frame deltas and focus switches through normal playback/view code in a diagnostic replay mode. Include pause/resume, movement, impacts, death expiry and a switch to a previously hidden city. The diagnostic replay is not a new network command or authoritative-state mutation route. Every repetition has owned state, warm-up and cleanup; measure the same 600 scripted frames and keep graphical correctness evidence outside timed sampling. This explicitly invoked measurement extends existing combat verification infrastructure and consumes one owned graphical slot. Missing private-display prerequisites mean unexecuted/nonzero, not desktop fallback. It is not a new default E2E scenario or a full graphical large-battle replay.

Capture a fresh pre-optimization `mise run test` timing and a full before `mise run ci` timing after the measurement harness is ready, and their final equivalents. The older 252.82s gate can establish historical correctness when source/environment match, but cannot substitute for missing runtime samples or the requested matched verification-speed baseline. Record actual test inventories and any added regression coverage; report common-workload partition comparisons alongside raw total time when coverage grows. Do not subtract guessed test costs or drop checks to improve the result. One full gate per boundary is sufficient; repeat only after changed inputs, failure or unresolved concern.

### 2. Count defined work, not an invented total of all calculations

Provide opt-in per-match/per-playback operation counters with a versioned schema and `--work-counters` on profile commands. Use integer increments at defined operation sites, no per-operation timestamps or strings. Count at least: world-view builds and unit visits; sort invocations and elements sorted; unit DTO projections and route/visited elements copied; local-observation builds and actor/reservation entries examined; opponent/range and splash candidates examined; BFS searches, cells dequeued and neighbor edges examined; occupancy checks and queued candidates examined; profile resolutions/cache misses; snapshot and serialization calls/bytes; playback index builds, event entries examined, full pose samples and HUD section refreshes. Record cache hits/misses where caching is introduced. Unsupported counters are marked unavailable, not zero. Count equivalent semantic operations on both implementations; optimized bypasses must not merely stop instrumentation.

Counts describe algorithmic work and are not CPU instructions, FLOPs, energy or a weighted score. Report each category independently, per tick and per active-unit-tick where meaningful, plus whole-workload totals. Aggregate phase attribution and counters must not double-count into a fictitious grand total. Peak/mean alive, deployed, queued, reserve and dying counts and the sum of deployed actors over ticks distinguish actual combat from a large idle queue. Profile setup and match construction too, so lookup precomputation costs remain visible.

Normal gameplay keeps detailed counters disabled. Capture before/after timing with counters disabled and separate matched counting runs; record counter overhead on a representative workload. Small hand-checkable fixtures verify counter semantics, reset/disposal, no overflow within declared bounds and identical ordered state/events with counters enabled/disabled. Deterministic relative-work regressions belong in cheap tests; machine-dependent timing thresholds do not. Useful assertions include no splash-candidate examination for cap-one attacks, one local-observation build per relevant city/stage, no unit DTO projection solely for enemy bookkeeping, and at most one full pose sample per visible actor per frame.

### 3. Test one genuinely large fight with a fixed workload

Add `mise run test-scale --scenario large-battle --seed 1` and `mise run profile-scale --scenario large-battle --sizes 128,512,2048 --seed 1 --iterations 3 --configuration Release`. The named large correctness test is mandatory before/after implementation acceptance and explicitly selectable without running other suites or Godot. It is not added to every routine cheap-test run or multiplied across the full campaign/graphical matrix. Full CI alone must not be reported as large-scale acceptance. Small fixture/counter regressions remain in the normal cheap gate.

Use one city battlefield with a valid 32-column by 8-row offset-hex board: 256 cells, reciprocal local neighbors, six normal render anchors/capacity, protected opposing rear bands and adjacent neutral front bands, and ordinary siege links. Create 1,024 adventurers and 1,024 skeletons, evenly split among the four ordinary archetypes on each side, using validated test-owned setup, stable ids and seed 1. Keep normal level-one health/damage, movement/attack/death timing and size two. Allocate sufficient test-owned food so reserve shortages do not replace combat. This is synthetic scale coverage, not an ordinary-economy/balance claim; no resources or altered board escape into ordinary strategies or process/UI commands.

Run exactly 600 ordinary fixed ticks with no scripted kills, damage, transfers or teleports during the measured window. Require at least 256 simultaneously deployed actors, including at least 128 of each faction at the same checkpoint, nonempty queues, landed attacks, casualties and actual subsequent admission of initially queued actors. Check board/capacity/anchor/faction/transit ownership, identity conservation across living/dying/removed sets, queue progress and bounded event retention at deterministic checkpoints and after the window. Record initial, checkpoint and final ordered state/event digests; consume event evidence often enough not to lose it through history truncation. Smaller samples use the same board, archetype proportions, seed and 600-tick horizon; if a smaller fight terminates naturally sooner, stop and report its actual ticks and terminal point rather than padding with no-op calls. The 2,048-actor case must exercise the full window. Record shape and active-unit-ticks instead of claiming actor count alone explains timing.

Set a 600-second hard wall bound per test/iteration and an overall profile bound derived from warm-up plus requested repetitions; interruption/failure returns nonzero and disposes every match. Setup/assertions/digests are outside measured stepping and separately timed. The large test must actually execute before and after; an unavailable or timed-out run is incomplete evidence. Establish the fixture and references on unoptimized code first, and never reduce 2,048 actors, active thresholds or window length afterward to manufacture a gain. Report this as a fixed-window stress pass, not full-battle completion, native frame performance, default-board capacity or twenty-wave balance. Existing normal-completion and ordinary campaign tests retain those responsibilities.

### 4. Reuse authoritative views at explicit mutation stages

Add narrow ordered queries for living enemy identity/destination, counts and soldier membership, retaining queued/reserve inclusion and dying exclusion. Replace snapshot-based cleared-city, transfer and engagement bookkeeping. Observe cleared cities before redistribution and refresh membership afterward. Retain survivor order, integer remainders, protected admission bounds and stall/defeat precedence.

Within cleanup/advance, admission and action selection, share an ordered authoritative view and needed id/city/faction indexes. Refresh after removals, casualties, elimination, admission, transfer or relevant profile changes. Preserve the initial action-stage observation and subsequent ordered movement arbitration. An admission call may reuse its exact first available entry position (including absence) by city/faction/size/band while occupancy revision is unchanged; clear that derived view after each placement and still examine every queued candidate in the original order. This is stage-local availability reuse, not event-driven scheduling. Never use tick number alone for invalidation; commands and direct test entry points can mutate a world at the same tick. Buffers are owned, bounded and cannot escape into events, snapshots or retained observations. Arch remains the only unit store; these are derived indexes, not competing authority.

### 5. Remove redundant exact decision work

Share immutable city-local reservation/actor observation payloads across actors, keeping each actor's decision sequence separate. Preserve omission of action sequence and health-only changes from the current observation contract. Local movement/casualty/admission/transfer invalidates relevant observations; unrelated cities and nonlethal health changes do not reroll decisions.

Implement the cap-one splash early return after argument validation. For larger caps, use local faction groups and preserve primary-first, distance/initiative/seed ordering. Compute city exposure once per impact-stage view and only consult it for city-target attacks; share id lookups for defense impacts and local groups for defense targeting. Select the best distance/initiative group without sorting irrelevant candidates, then preserve ascending identity within exact ties and the existing seeded choice. Unordered direct callers still need canonical ties. Do not replace the existing random choice with reservoir sampling or consume additional random decisions.

Replace transient BFS frozen-map construction with ordinary privately owned dictionaries/read-only views first; dense board-indexed buffers remain a measured follow-up within this change only if needed and equivalence tests pass. Authored cell ids need not be dense. Preserve BFS reachability, all shortest predecessors, exclusions, support screening, goal/anchor tie order and the single-search-per-actor approach. Share local screening candidates and immutable static city-distance/goal-cell data when repeated use warrants it; never cache occupancy-dependent routes across unsafe mutation boundaries. Retain long-lived frozen configuration maps. More complex route algorithms, probabilistic hashes and approximate targets remain deferred.

### 6. Reuse profiles, catalogs and detached snapshot work

Project only matching authoritative units. One canonical ordered view feeds a complete match snapshot; each city uses its soldier projection once for payload and food forecast. Standalone city snapshots remain valid. Use direct internal building/research/wave lookups instead of materializing public catalogs for single commands. Resolve immutable profiles once per validated type/level/rank/boss key, bounded to actually requested supported combinations; preserve decimal rounding, overflow rejection, boss/research ordering and wounded current health. Never precompute unsupported overflowing levels merely because the authoring bound is 256.

Reuse immutable recruitment quote calculations when research is unchanged. Reuse food-forecast work within a snapshot/stage; any longer-lived cache must key all relevant food, living membership, level, type and phase inputs, including same-tick mutations. Prefer scoped reuse over another persistent invalidation system. Reuse private board/campaign/catalog templates without removing wire fields. Returned nested arrays, including board neighbors, campaign entries, recruit lists, decisions, routes and receipt ids, stay detached from authority and independent snapshots. No pool-backed array outlives its owner. Profile/forecast caches reset with their match and never retain cross-match state.

### 7. Reduce presentation work without changing sampled behavior

Build immutable current/previous playback indexes and a pending-death lookup when snapshots/events are accepted; preserve exact event cursors, gap recovery, admission timing, buffered death expiry and reconnect baselines. Per frame, select the correct time-dependent state without rebuilding/sorting complete snapshot indexes. Avoid an event-history scan for each view.

Arrange frame work as state/view synchronization, ordered event application, then a single final full pose sample per visible deployed actor. Keep required event source positions available without advancing the animation tree twice. Hidden-city views retain current logical state, event cursors and effect lifecycle but skip skeletal evaluation; focusing them immediately samples the correct current pose without historical sounds, duplicate impacts or stale strikes. Preserve pause/death/frozen aim behavior and cleanup while hidden.

Cache immutable animation lengths, bone indices and Godot names after rig binding, and cache route segment/cumulative lengths with route points. Invalidate/dispose them with the rig/layout/match. Keep the same route geometry and tolerances; no approximate authority math. Split HUD invalidation by displayed economy, selection, phase, roster/connection and status inputs instead of blanket combat revision; current health, participation, research quotes, food forecasts and feedback must still update when changed. Bounded existing stockpile/effect/audio mappings remain intact.

Cheap playback/layout/invalidation regressions own numerical and lifecycle equivalence. Extend existing combat/reconnect source slices only for actual rig sampling, focus restoration and no-replayed-effect behavior cheaper tests cannot prove; retain their setup and all cooperative assertions. Use actual input and fresh observations/frames. Add no graphical big-fight replay or new default UI scenario. The separate presentation profile has one bounded replay and measured overhead, not an exhaustive E2E matrix.

### 8. Optimize verification overhead independently

Reuse one before snapshot per strategy decision, command and before-state assertion, refreshing after each accepted action. Keep serialized session wire assertions. Replace the first-level-five participant's projected whole-army observation with the equivalent narrow query, preserving the earliest qualifying wave.

Separate investment and other assertions from diagnostic interpolation. Retain compact success summaries covering all six resources, spending/production, recruitment/progression, food, rewards, wave ticks and casualties; bounded recent records expand on failure and explicit trace enables greater detail. Preserve all 21 strategies, seeds 0/1/123, four solo families, cooperative sizes 2/3/4, serialized twenty-wave campaign and the in-process fallback. Attribute these improvements to verification/preparation, not combat stepping. Do not time discarded formatting as runtime work or weaken checks to improve numbers.

### 9. Prove equivalence and report each outcome honestly

Capture pre-optimization canonical references for ties, simultaneous arrival/impact/death, admission, transfer, pause/resume, session end, ordinary wave outcomes and large-fixture checkpoints. Normalize only session/match identity; retain ids, order, seeds, configuration, decisions, reservations and requests. Full-state hashing is correctness work outside measured stepping. Mutation-isolation tests cover nested public arrays and same-tick cache freshness. Presentation references include sampled poses, event consumption, focus switches and death deadlines.

Publish separate runtime and verification tables in `docs/verification.md`, linking raw ignored logs. For every metric show baseline, after, absolute delta and `(after - before) / before * 100`; lower-is-better costs must label negative changes as reductions. Zero baselines use absolute changes with relative change unavailable. Include medians and ranges across measured repetitions, p95/p99 only for a sufficient frame/tick sample distribution, exact work counts, input equivalence and coverage. Do not turn three whole-campaign observations into a credible tail-latency distribution. Explain regressions, noise, added coverage and missing runs. No promised percentage speedup or hard timing gate; reductions in operation counts alone do not establish lower CPU time. Retain per-area measurements to distinguish runtime fixes from test-harness fixes.

## Risks / Trade-offs

- [Stale caches change outcomes] -> Stage-owned views, explicit same-tick tests, no tick-only cache or escaping mutable buffers.
- [Target optimization changes ties] -> Canonical identity ordering, unchanged seed arithmetic and reference traces.
- [Large nominal army stays idle] -> Required simultaneous opposing deployment, impacts, casualties and queued admissions; report all population categories and active-unit-ticks.
- [Stress setup or instrumentation dominates] -> Separate setup/assertion/digest phases and counter-disabled timing; version measurement semantics.
- [Presentation sampling loses transient events] -> Apply events before one final pose, retain logical hidden state and verify actual rig/focus/reconnect behavior.
- [Verification gets faster while runtime regresses] -> Independent required baseline families and tables; no blended score or attribution from CI wall time.
- [Coverage expansion distorts testing-speed comparison] -> Inventory both runs, preserve the common workload and report added checks separately alongside raw totals.
- [Measurements exceed bounds or prerequisites are missing] -> Record failed/unexecuted, retain partial evidence and leave required performance acceptance incomplete; no automatic tool installation or smaller substitute stress pass.

## Migration Plan

1. Inspect source/environment and prior gate evidence. Add only measurement/counter/fixture scaffolding and correctness references, validate it with cheap checks, and freeze its unoptimized revision.
2. Capture all ordinary/scale/snapshot/presentation runtime baselines plus fresh cheap-test and full-CI timing baselines. Freeze workload digests, counter version, build settings, budgets and bounds before optimizing.
3. Implement authoritative query/view, decision, snapshot/catalog and presentation fixes in dependency order. Run affected cheap regressions and matched selected profiles after relevant changes; retain per-area evidence.
4. Optimize campaign harness/diagnostics separately and attribute its gains. Complete affected combat/reconnect UI checks through existing owned slices and update documentation within each area.
5. Perform locked restore and C# formatting, final required checks/full CI, and the identical runtime, large-test and test-speed runs. Publish separate comparisons and limitations. Do not archive, publish or deploy.

Rollback reverts an affected optimization while retaining useful profiling and regression fixtures. No save, dependency or protocol migration is required. A failed or inconclusive optimization is reported explicitly rather than silently counted as a performance success.
