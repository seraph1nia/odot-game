# Proposal

## Why

Verification repeats game flows through expensive real-time processes and graphical input: the recorded warm full gate took 780 seconds, including about 580 seconds of graphics, and retained 4 GB of evidence. Make C# acceptance tests the primary owner of game flows, preserving focused transport, rendering and package witnesses while reducing elapsed time and diagnostic overhead.

## What Changes

- Map each existing assertion to its cheapest meaningful owner before removing repeated process/UI work. Retain the complete ordinary twenty-wave strategy sample in C#, and extend ordinary serialized authority/session flows for reconnect, retries, upkeep, redistribution and terminal outcomes.
- Shorten the real-process campaign to transport/lifecycle witnesses while preserving all six stable network scenario selectors. The `authority-resume-victory` selector remains compatible; its full victory evidence moves to C# and its risk description explains the split.
- Keep all five source graphical slices selectable, but limit them to actual input routing, binding, focus, projection, rendering and lifecycle witnesses. Replace repeated packaged menu/friends/hosted campaigns with a small packed-resource and ordinary-input smoke.
- Add bounded accelerated authority stepping for owned verification only, without changing combat rules or interactive game speed. Keep real-time animation/input witnesses and real wall-clock transport deadlines.
- Add two isolated graphical workers with a serial override, bounded C# campaign concurrency and resource-aware overlap after shared preparation. Preserve ordered build/import/export mutations and required source gates before local exports.
- Bound and buffer diagnostic evidence, avoid duplicate full-snapshot transcripts, retain failure context and report elapsed time, concurrency, simulated ticks and evidence volume.
- Update command guidance and coverage records. Treat a 180–300 second warm local full gate as an optimization target, not a guaranteed CI deadline or a measured result.

## Capabilities

### New Capabilities

None; extend the existing verification capabilities.

### Modified Capabilities

- `coop-verification`: C# ownership of complete game/session flows, focused real-process and graphical witnesses, assertion migration and unchanged simulation under verification acceleration.
- `linux-test-execution`: bounded isolated graphical concurrency, shared resource admission, compact attributable evidence and recorded performance comparison.

## Impact

- `tests/Game.Core.Tests`: authority/session flow coverage and bounded campaign scheduling; existing gameplay/strategy invariants remain required.
- `tools/DevRunner`: scenario scope/scheduling, pacing arguments, evidence handling and smaller network/UI/package drivers; `src/Game/Main.cs`: owned verification pacing and diagnostic emission.
- `AGENTS.md`, `README.md`, `docs/verification.md`, `mise.toml` and relevant workflow command configuration: truthful commands, budgets and coverage ownership. Existing separate GitHub job workspaces remain independent; local source-before-export gates remain intact.
- No tool/dependency upgrades, game balance changes, protocol payload redesign, real Steam acceptance changes, publication or deployment. Preserve the completed `simplify-match-ui` implementation, existing edits and the 300-second Linux-package default.
- Planning uses existing evidence only; no tests are run during proposal creation. Implementation validation follows repository task-boundary guidance and does not require repeated full suites solely to populate benchmarks.
