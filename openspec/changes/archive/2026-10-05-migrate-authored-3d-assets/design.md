## Goals / Non-Goals

**Goals:** A finite explicit presentation catalog shared by buildings, labels, previews and verification; complete dependency/provenance coverage; authored rigs/equipment rather than detached props; new-source terrain while preserving stable array IDs and numerical traces; observable graphical quality and bounded resource cost.

**Non-Goals:** Numerical rule/profile/timing changes, renaming wire/save enums, rewriting session architecture, replacing Trio UI/audio, Blender authoring, downloads, source-repository writes, tool/dependency changes, release/version changes or speculative follow-up implementation.

## Decisions

1. **Explicit render catalog and immutable exports.** Required paths and canonical-role-to-presentation-name mappings are finite typed metadata, not filename guesses in render code. Retain copied GLB bytes exactly and record SHA-256, bytes and immutable source-relative paths. A complete old-model disposition inventory includes dormant files and support dependencies. Existing legacy notices/history remain attributable, but no old model/buffer/atlas/import survives as a runtime fallback. Alternative: switching only runtime paths would leave dormant export bundles and miss indirect previews/equipment.

2. **Honest substitutes, stable simulation keys.** Bakery/Farm, Woodcutter hut/Lumbermill, Magic academy/Arcanum, Bombard tower/CatapultTower, Knight/Swordsman and friendly Archer/Crossbowman use presentation labels only. Gold cargo uses a crate/parcel, provisions an open barrel and timber authored bridge planks; document these limitations rather than inventing gold/sack models. Distinct Gold Mine/Metal Mine, Weaver, Stonecutter, Town hall and Market now use dedicated source silhouettes. The fixed home may use Tree house; the fixed defender uses Arrow tower. Level-two upgrades use available props and a measured shrine plinth for supporting towers. The Bakery has no windmill fan; remove that obsolete animation integration rather than fabricate one.

3. **Authored rig/sockets/clips are presentation adapters.** The source shared rig has `root`, hands and `weapon_socket.L/R`; exports contain equipped weapon/shield/offhand geometry. Validate actual imported bindings and keep those authored equipment transforms instead of hiding them and attaching legacy weapons. Explicitly require `idle`, `walk`, `run`, `attack`, `hit`, `death`; enforce loops for locomotion and one-shots for actions in memory without editing GLBs. Source attacks have 24 frame intervals at 24 fps, but actual GLB keys span frame 1 through frame 25 (1/24 through 25/24 seconds), not zero through one. Their maximum attack/draw pulse is frame 13 (13/24 seconds); preserve the exported one-frame offset and map that pose to the unchanged authoritative impact tick in presentation. Cheap byte-contract checks exposed this offset before rig integration. Keep legacy `Game.Core` playback helpers/frozen tests unchanged: their old measured markers are not numerical gameplay and are no longer the new-render integration's marker source. Root horizontal motion and method callbacks remain disallowed. Standalone authored props cover cosmetic shots and inventory validation; embedded equipment remains the live attachment. Alternative: retaining old rigs or automatic retargeting violates provenance and risks timing/weapon transforms.

4. **Preserve pointy-top world anchors by rotating source terrain.** Rotate native flat-top meadow/stream tiles 90 degrees at scale `existing pointy radius / 2.55`; retain existing X/Z plot and combat anchor positions. A straight authored stream cannot reproduce the former alternating bends. Instead run it along one fixed row at the settlement edge, where neighboring centers lie on the now-horizontal authored north/south connector axis. Replace one stream cell with the identically oriented/normalized complete authored woodland bridge, not a meadow underneath its water. Reuse its bank/water ground origin, including intentionally submerged supports. Shallow terraces (increments smaller than scaled foundation depth) and lower banks replace unavailable legacy slope/mountain meshes; boulders provide peripheral rocky outcrops. This changes only decorative composition, not combat topology, anchors or selection IDs.

5. **Batch all authored terrain meshes with their materials.** Ordinary meadow and stream exports contain multiple material-bearing mesh nodes. Flatten their existing node transforms and combine imported surfaces by material for reusable terrain templates, then reuse those in existing bounded chunked MultiMeshes. This is integration of existing authored vertices, not new asset authoring. Never assume a source scene contains exactly one mesh. Keep complete decorated bridge geometry as a single installed scene and avoid double-rendering its base cell. Observe actual installed cell transforms, template bounds, stream connectors and material/instance counts, not only calculated ranges. Decorations remain deterministic render-only sparse clusters outside plot/battle sightlines. Alternative: a full scene per cell multiplies nodes/draws; procedural replacements violate source-only scope.

6. **Sequential migration, then polish.** First vendor/bind all required exports and remove old dependencies while retaining existing consumers/controls. Only after the mapping works tune silhouette scale, framing, clustering and shared menu/match lighting. Preserve original materials and adjust lighting rather than repainting source content. Use measured footprint placement (including deliberate authored below-ground geometry) and actual deck contacts, not hand-tuned floating offsets. Software-rendered captures judge composition separately from green assertions.

7. **Reuse admitted coverage.** Extend cheap pure projection/catalog/provenance and terrain/binding checks; extend existing launcher/economy/combat/roster and packed checks without adding a full campaign or option matrix. Add a tiny independently selectable graphical asset/roster evidence slice only if existing ordinary coverage cannot establish import/socket/storage behavior; record its risk, bounded setup and maintenance cost first. Keep existing cooperative, food, healing, return, retire, paused/reconnect and numerical assertions intact. Full after CI runs once at the coherent task boundary after relevant focused checks pass.

8. **Source-independent rendering investigation and exact live admission.** Latest steering authorizes game-side optimization only, not editing the evolving asset exports. Compatibility has no automatic identical-mesh instancing. A finite material-compatible direct-array static candidate retained unsupported/tangent-space/transparent/LOD geometry and passed native buffer/cache controls, but its 23% draw reduction did not materially improve render/probe latency; nonzero image differences are not waived. It and the ineffective pine candidate were retired from compiled gameplay, preserving scratch/evidence. Original hierarchies remain. Read-only owned live probes now use a fresh actual post-draw frame without the input/layout probe's two-future-frame settling barrier; input/layout probes retain that barrier. Twelve live observations/four immutable captures still fit the original 12-second bound, with only exact persistence separately awaited under 30 seconds. No simulation slowing or witness weakening. Existing scene/terrain/bounds caches invalidate on source/import/engine/backend/cache-version changes and retain normal resource sharing. See `docs/runtime-rendering.md` for official references, quantitative comparison and the passing motion/capture seam. Steering 015 subsequently proved exclusive owner-thread ENet guest service through the documented original-API passthrough, without global poll/transport/channel/security changes; generation/thread/reentrant/frame/duplicate-owner guards and lifecycle restoration preserve original authority/solo/host/Steam modes. A pre-Ready floor/own-Ready-ack observer and post-progression current-pause handoff pass the focused four-view gate, with exact frame/action/camera/pixel receipts (`docs/enet-guest-cadence.md`). Steering 016 corrected general-combat casualty admission through the existing single ordered driver: latest current eligibility, the same predicate on the actual accepted pause receipt, at most three own-pause/resume attempts within the unchanged deadline, fresh revision floors and exact frozen-frame identity/target/body validation (`docs/current-casualty-admission.md`). Rejected/stale/terminal/unreadable receipts authorize neither capture nor speculative resume; cancellation awaits the watcher. Strict source/packed inventory projection recognizes actual `.import` and `.remap` mappings without changing the required set. ## Risks / Trade-offs

- [Source exports have no standalone open-source license] → Record owner permission verbatim and only authored required exports; do not imply reference rights or Trio clearance.
- [Importers may represent bone-parented props differently] → Validate actual imported sockets and equipment hierarchy/poses through Godot consumers before accepting attachment assertions.
- [Detailed building maps increase memory despite fewer files] → Record source bytes, imported resources/materials, scene nodes, draw/primitive observations and compare owned evidence; no native-GPU claims.
- [Straight source stream cannot mimic old bend pattern] → Explicitly relocate the cosmetic river to a compatible settlement-edge row and validate shared edge/water continuity and bridge substitution.
- [Larger silhouettes or trees can hide controls/units] → Keep plot/battle masks clear, measure bounds, use actual overview/near/far captures at both sizes and retain real picking/control checks.
- [New names can drift from canonical research/catalog text] → Use one presentation projection for displayed roles/producer help while keeping requests, selectors and saved/protocol IDs unchanged.

## Migration Plan

1. Finish the concrete map/provenance, strict planning validation and source checks; preserve successful before CI and owned baseline captures.
2. Copy selected immutable exports; implement the catalog, model/rig adapters and source terrain integration; validate every required scene through the actual importer and consumer, then remove old model/support/import bundles.
3. Run cheap and selected launcher/economy/combat/roster checks while adapting; do not refresh frozen numerical digests or relax gameplay checks.
4. Once migration works, tune render-only composition/light/scale and inspect owned populated/active captures plus render observations.
5. Format changed C# after locked restore; run full after CI (source, network, UI, sequential exports and both package smokes), retain timing/evidence and limitations.
6. Update docs/provenance/recommendations; sync/archive only this change and commit the implementation handoff. Firstmate separately starts no-mistakes. No direct push, merge or release. A conventional revert of the feature commit is the rollback; never rewrite source/history or delete user state.
